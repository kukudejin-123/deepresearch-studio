# 02 术语与概念

本文档统一项目中涉及的核心概念定义，避免文档与代码中的歧义。

## 2.1 智能体框架

### DeepAgents

LangChain 官方推出的“开箱即用”智能体框架（`deepagents` 包），核心工厂方法 `create_deep_agent()` 接收模型、系统提示词、工具列表、检查点器和子智能体列表，返回一个编译好的 LangGraph 图。

**关键概念**：

- **主智能体（Main Agent）**：调度中心，负责任务理解、步骤规划、子智能体调度和最终汇总；
- **子智能体（Subagent）**：以字典形式声明（name/description/system_prompt/tools），主智能体通过名为 `task` 的内部工具调用它们；
- **Orchestrator-Workers 模式**：本项目采用的架构——主智能体是 Orchestrator，三个专家助手是 Workers。

### LangGraph

LangChain 生态的图编排运行时。智能体本质上是一张状态图（StateGraph），节点（模型节点、工具节点）之间通过边连接，状态（messages 等）在节点间流转。

**关键概念**：

- **检查点（Checkpoint）**：图执行到某一步的完整状态快照，按 thread_id 存储，用于会话恢复；
- **Checkpointer**：检查点存储器，本项目实现了 SQLite/PostgreSQL/内存三种；
- **astream**：异步流式执行接口，持续产出各节点的状态片段（chunk）。

### LangChain

模型与工具的抽象层。`@tool` 装饰器把普通函数变成模型可调用的工具（函数签名和 docstring 会暴露给模型）；`init_chat_model` 统一初始化各种模型提供方。

## 2.2 RAG 相关

### RAG（检索增强生成）

Retrieval-Augmented Generation：先从知识库检索相关文档，再把文档作为上下文交给模型生成回答。相比纯模型生成，RAG 的结论有据可查，且知识可实时更新（无需重新训练模型）。

### Embedding（向量化）

把文本映射为高维向量（如 1024 维），语义相近的文本向量距离也近。本项目通过 OpenAI 兼容接口调用百炼 `text-embedding-v3` 模型。

### FAISS

Facebook 开源的向量相似度检索库。`IndexFlatL2` 是最基础的索引类型：暴力计算查询向量与库内向量的 L2 距离，百万级以下数据量完全够用。

**关键概念**：

- **分片（Chunk）**：长文档切分的小块（本项目 500 字符、重叠 80），检索的基本单位；
- **集合（Collection）**：一个 FAISS 索引 + 文档存储 + 元数据，对应磁盘上一个目录；
- **L2 距离**：欧氏距离，越小越相关。

### 用户私有库 vs 共享库

本项目的知识库分层设计：`VECTOR_STORE_DIR/user_{id}/` 是用户私有库（只有本人可见），`VECTOR_STORE_DIR/` 根目录是共享库（所有用户可见，用于演示数据）。

## 2.3 工程概念

### JWT（JSON Web Token）

无状态认证令牌，由三部分组成（Header.Payload.Signature）。服务端用密钥签名，客户端每次请求携带，服务端验签后即可信任其中的用户身份，无需查会话表。

### 检查点持久化

LangGraph 检查点落盘到数据库，服务重启后可按 thread_id 恢复会话上下文。**同步实现（SqliteSaver）在异步图（astream）中会直接报错**——这是本项目踩过的坑，必须用异步实现（AsyncSqliteSaver/AsyncPostgresSaver）。

### 任务队列

把 Agent 执行从请求进程中解耦：API 进程只负责入队，执行在独立 worker 进程完成。本项目实现了 memory（进程内 asyncio）和 arq（Redis 分布式）两种。

### 事件桥（Event Bridge）

跨进程事件转发机制。worker 进程产生的执行事件通过 Redis Pub/Sub 发布，API 进程订阅后转发给 WebSocket 连接。

### 协作式取消

跨进程取消的执行策略：取消接口把任务状态置为 cancelled，执行侧在流式循环中定期检查状态并主动收尾。相比强杀（无法跨进程），协作式更安全。

### 断线回放

WebSocket 断开期间丢失的事件，在重连后通过 REST 接口按 seq 增量拉取补齐。事件带全局递增的 seq，前端据此去重。

### LLM-as-judge

用大模型评审另一个模型的输出。按 rubric（评分维度）打分，是 Agent 质量评估的标准做法。本项目使用 correctness/completeness/groundedness 三维。

### 确定性检查

不调用 LLM 的评测方式：检查答案是否包含必须出现的关键词、是否包含禁用语、期望的工具是否被调用。零成本，可每次 CI 运行。

## 2.4 项目专有名词

| 名词 | 含义 |
| --- | --- |
| 格物 | 项目中文名，取“格物致知”之意 |
| 深研 | 前端界面品牌名 |
| 一主三从 | 主智能体 + 三个专家子智能体的架构 |
| 会话目录（session_dir） | 每个任务独立的工作目录，产物落盘位置 |
| thread_id | 任务会话 ID，同时用于检查点、事件、WebSocket 定向 |
| 种子文件（seed_files） | 评测用例预置的上传文件，文件读取类用例的输入 |
| 冒烟模式（--mock） | 评测 CLI 的框架自检模式，假执行器 + 假评审，不调用外部服务 |
