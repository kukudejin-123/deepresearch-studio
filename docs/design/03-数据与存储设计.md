# 03 数据与存储设计

## 3.1 存储总览

系统使用五类存储，全部可通过环境变量配置路径：

| 存储 | 技术 | 默认路径 | 内容 | 访问模式 |
| --- | --- | --- | --- | --- |
| 会话检查点 | SQLite / PostgreSQL | app/data/checkpoints.db | LangGraph 检查点 | 多进程共享（WAL） |
| 任务存储 | SQLite | 同上（同库不同表） | 任务状态与元数据 | 多进程共享（WAL） |
| 事件存储 | SQLite | app/data/events.db | 执行事件（append-only） | 多进程共享（WAL） |
| 用户存储 | SQLite | app/data/users.db | 用户账号与密码哈希 | 单进程（API） |
| 向量库 | FAISS 文件 | app/data/vector_store/ | 向量索引 + 文档存储 | 读多写少 |

## 3.2 会话检查点（Checkpoint）

### 3.2.1 三种实现

```python
# app/agent/checkpointer.py
CHECKPOINTER_TYPE=sqlite    → AsyncSqliteSaver（默认，单机）
CHECKPOINTER_TYPE=postgres  → AsyncPostgresSaver（生产，多 worker 共享）
CHECKPOINTER_TYPE=memory    → InMemorySaver（调试，重启丢失）
```

### 3.2.2 为什么必须用异步实现

LangGraph 的 `astream` 只调用检查点的异步接口（`aput`/`aget`）。同步的 `SqliteSaver` 没有这些方法，调用时直接报错：

```
The SqliteSaver does not support async methods.
Consider using AsyncSqliteSaver instead.
```

这是本项目第二期改造时真实踩到的坑（详见面试文档踩坑复盘）。

### 3.2.3 表结构（LangGraph 自动创建）

- `checkpoints`：thread_id、checkpoint_id、父检查点、序列化状态；
- `writes`：待应用的写入操作（用于中断恢复）。

### 3.2.4 PostgreSQL 模式

```python
_checkpointer_cm = AsyncPostgresSaver.from_conn_string(dsn)
saver = await _checkpointer_cm.__aenter__()
await saver.setup()
```

依赖做成可选 extra（`uv sync --extra postgres`），默认安装不引入 psycopg。

## 3.3 任务存储（TaskStore）

### 3.3.1 表结构

```sql
CREATE TABLE tasks (
    thread_id TEXT PRIMARY KEY,
    user_id INTEGER,           -- 第一期新增（含旧库迁移）
    query TEXT NOT NULL,
    status TEXT NOT NULL,      -- running/completed/failed/cancelled
    error TEXT,
    created_at TEXT NOT NULL,
    updated_at TEXT NOT NULL
)
```

### 3.3.2 状态机

```
create() → running
            ├── set_status(completed)   # 正常结束
            ├── set_status(failed, error)  # 异常
            └── set_status(cancelled)   # 用户取消/协作式取消
```

### 3.3.3 旧库迁移

第一期给 tasks 表加了 user_id 列。SQLite 支持 `ALTER TABLE ADD COLUMN` 原位迁移：

```python
columns = {row["name"] for row in conn.execute("PRAGMA table_info(tasks)")}
if "user_id" not in columns:
    conn.execute("ALTER TABLE tasks ADD COLUMN user_id INTEGER")
```

### 3.3.4 并发写入

API 进程（提交/取消时写）与 worker 进程（结束时写）并发访问同一文件：

```python
conn = sqlite3.connect(str(self.db_path), timeout=10)
conn.execute("PRAGMA journal_mode=WAL")
conn.execute("PRAGMA busy_timeout=10000")
```

WAL 模式支持多进程读写并发，busy_timeout 避免瞬时写锁直接报错。

## 3.4 事件存储（EventStore）

### 3.4.1 表结构

```sql
CREATE TABLE task_events (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    thread_id TEXT NOT NULL,
    seq INTEGER NOT NULL,        -- thread_id 内单调递增
    event TEXT NOT NULL,         -- tool_start/assistant_call/task_result/...
    message TEXT NOT NULL,
    data TEXT NOT NULL DEFAULT '{}',  -- JSON
    created_at TEXT NOT NULL,
    UNIQUE (thread_id, seq)
)
CREATE INDEX idx_task_events_thread_seq ON task_events (thread_id, seq)
```

### 3.4.2 seq 的分配

```python
row = conn.execute(
    "SELECT COALESCE(MAX(seq), 0) AS max_seq FROM task_events WHERE thread_id = ?",
    (thread_id,),
).fetchone()
next_seq = row["max_seq"] + 1
```

**为什么用 MAX+1 而不是自增 id**：自增 id 是全局的，不同 thread 的 seq 不连续；前端按 thread 去重需要 thread 内连续的 seq。

### 3.4.3 增量查询

```sql
SELECT * FROM task_events
WHERE thread_id = ? AND seq > ?
ORDER BY seq ASC LIMIT ?
```

前端记录已收到的最大 seq，重连后传 `after_seq` 拉取缺口。

## 3.5 用户存储（UserStore）

### 3.5.1 表结构

```sql
CREATE TABLE users (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    username TEXT NOT NULL UNIQUE,
    password_hash TEXT NOT NULL,  -- PBKDF2-SHA256 hex
    salt TEXT NOT NULL,           -- 随机盐 hex
    created_at TEXT NOT NULL
)
```

### 3.5.2 密码哈希

```python
digest = hashlib.pbkdf2_hmac(
    "sha256",
    password.encode("utf-8"),
    bytes.fromhex(salt_hex),   # 16 字节随机盐
    100_000,                   # 迭代次数
)
```

**为什么用标准库而不是 bcrypt**：PBKDF2 是 NIST 推荐标准，标准库实现无额外依赖；10 万次迭代在本机约几十毫秒，可接受。

**校验时序安全**：`hmac.compare_digest(expected, actual)` 防时序侧信道。

## 3.6 向量库（FAISS）

### 3.6.1 目录结构

```
app/data/vector_store/
├── user_1/                    # 用户 1 私有库
│   └── collection_a1b2c3d4/   # ASCII slug（名称哈希）
│       ├── index.faiss        # 向量索引（serialize_index 字节）
│       ├── index.pkl          # 文档存储（pickle）
│       └── meta.json          # 集合元数据（中文名、文件列表）
├── user_2/
└── collection_e5f6g7h8/       # 共享库（根目录）
```

### 3.6.2 为什么用 ASCII slug 目录名

FAISS 的 C++ 写入层（`faiss.write_index`）在 Windows 上无法打开含非 ASCII 字符的路径——包括中文项目目录和中文系统用户名。解决方案：

```python
def _slugify(self, name: str) -> str:
    ascii_part = re.sub(r"[^A-Za-z0-9_-]+", "", name)[:20]
    digest = hashlib.sha1(name.encode("utf-8")).hexdigest()[:8]
    return f"{ascii_part or 'collection'}_{digest}"
```

中文展示名保留在 meta.json 的 name 字段，对上层透明。

### 3.6.3 索引序列化

```python
# 写入（绕开 C++ 文件 IO）
index_bytes = faiss.serialize_index(store.index)
(collection_dir / "index.faiss").write_bytes(index_bytes.tobytes())

# 读取
raw = (collection_dir / "index.faiss").read_bytes()
index = faiss.deserialize_index(np.frombuffer(raw, dtype=np.uint8))
```

### 3.6.4 用户私有库 + 共享库

```python
def _resolve_knowledge_bases(self) -> list[VectorKnowledgeBase]:
    user_id = get_user_context()
    if user_id is None:
        return [self._shared_kb]
    return [self._user_kb(user_id), self._shared_kb]  # 私有优先
```

集合发现时重名以私有库为准；检索时按名字找到承载它的库。

## 3.7 数据一致性

### 3.7.1 检查点与任务状态的关系

两者独立：检查点保存 Agent 执行上下文（messages 等），任务状态保存任务级元数据。任务失败时检查点可能已写入部分状态——这是设计使然（支持未来实现 resume）。

### 3.7.2 事件与任务状态的关系

事件是 append-only 的流水，任务状态是最终结论。回放接口返回事件，任务查询返回状态，两者通过 thread_id 关联。

### 3.7.3 多进程写入冲突

所有 SQLite 存储统一 WAL + busy_timeout。任务写入频率低（每个任务几次状态变更），冲突概率极低；即使冲突，busy_timeout 会等待而非报错。
