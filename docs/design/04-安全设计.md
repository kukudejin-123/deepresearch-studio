# 04 安全设计

## 4.1 威胁模型

### 4.1.1 资产识别

| 资产 | 价值 | 威胁 |
| --- | --- | --- |
| LLM API 配额 | 高（直接花钱） | 恶意用户疯狂提交任务 |
| 用户数据（任务/文件） | 高（隐私） | 越权访问他人资源 |
| MySQL 业务库 | 极高（生产数据） | 模型生成危险 SQL |
| 服务器磁盘 | 中 | 恶意上传大文件 |
| 用户账号 | 高 | 暴力破解 |

### 4.1.2 攻击面

1. **未认证访问**：直接调接口；
2. **越权访问**：知道他人 thread_id 后访问其资源；
3. **SQL 注入**：诱导模型生成 `DROP TABLE`；
4. **路径穿越**：上传 `../../etc/passwd` 或下载任意文件；
5. **资源耗尽**：高频提交任务打爆配额；
6. **凭证窃取**：JWT 泄露（query 参数传输的固有风险）。

## 4.2 认证设计

### 4.2.1 JWT 流程

```
注册/登录 → 服务端签发 JWT（sub=user_id, exp=24h）
    → 客户端存储 localStorage
    → 每次请求带 Authorization: Bearer <token>
    → 服务端验签 → 提取 user_id → 查询用户是否存在
```

### 4.2.2 FastAPI 依赖注入

```python
async def get_current_user(
    request: Request,
    credentials: Optional[HTTPAuthorizationCredentials] = Depends(bearer_scheme),
) -> dict:
    if not auth_enabled():
        return dict(DEV_USER)  # 开发模式
    if credentials is None:
        raise HTTPException(401, "未登录或登录已过期")
    payload = decode_access_token(credentials.credentials)
    if payload is None:
        raise HTTPException(401, "登录凭证无效或已过期")
    user = get_user_store().get_user(int(payload["sub"]))
    if user is None:
        raise HTTPException(401, "用户不存在或已被删除")
    return {"id": user["id"], "username": user["username"]}
```

所有资源接口通过 `Depends(get_current_user)` 保护。

### 4.2.3 三种 token 传递方式

| 场景 | 方式 | 原因 |
| --- | --- | --- |
| 普通 HTTP 接口 | Authorization 头 | 标准做法 |
| 浏览器 `<a href>` 下载 | ?token= 查询参数 | 链接无法带请求头 |
| WebSocket | ?token= 查询参数 | 浏览器 WebSocket 不支持自定义头 |

**query 参数的固有风险**：token 会出现在浏览器历史、服务器访问日志、Referer 头中。缓解措施：token 有效期默认 24 小时（可调短），下载接口的 token 校验与请求头完全一致。

### 4.2.4 开发模式

`AUTH_ENABLED=false` 时退化为单一虚拟用户（id=0, username=dev），方便本地无登录调试。生产环境必须设为 true。

## 4.3 授权与资源隔离

### 4.3.1 隔离模型

```
output/user_{user_id}/session_{thread_id}/    # 产物
updated/user_{user_id}/session_{thread_id}/   # 上传暂存
vector_store/user_{user_id}/                  # 私有知识库
tasks.user_id                                 # 任务归属
```

### 4.3.2 归属校验

```python
def _get_owned_task(thread_id: str, user: dict) -> dict:
    task = task_store.get(thread_id)
    if task is None or task.get("user_id") != user["id"]:
        raise HTTPException(404, "任务不存在")  # 不暴露存在性
    return task
```

**为什么返回 404 而不是 403**：403 会告诉攻击者“这个资源存在但不属于你”，404 则完全隐藏资源存在性。

### 4.3.3 文件路径边界

```python
def _resolve_within(path: str, root: Path) -> tuple[Optional[Path], Optional[str]]:
    abs_path = Path(path).resolve()
    root_abs = root.resolve()
    if not abs_path.is_relative_to(root_abs):
        return None, "拒绝访问: 只能访问当前用户名下的文件"
    return abs_path, None
```

`resolve()` 先解析 `..` 和符号链接，再判断是否在用户根目录内。

### 4.3.4 WebSocket 归属校验（第二期修正）

```python
task = task_store.get(thread_id)
if task is not None and task.get("user_id") != current_user["id"]:
    await websocket.close(code=4404, reason="任务不存在或不属于当前用户")
    return
# 任务不存在时允许连接（前端先连后提交流程）
```

**修正历史**：最初要求“任务必须存在且属于本人”，但前端是“先建 WebSocket 再提交任务”（thread_id 由客户端预生成），正常流程被 403 挡死。修正为“任务不存在时允许预订阅（thread_id 为 UUID 且按用户本地存储，猜测他人 thread_id 可行性可忽略），任务属于他人时拒绝”。

## 4.4 SQL 注入防护

### 4.4.1 威胁

数据库助手直接执行模型生成的 SQL。模型可能被诱导（提示注入）生成 `DROP TABLE drugs` 或 `SELECT ... INTO OUTFILE`。

### 4.4.2 防护层（sql_guard.py）

```python
def validate_readonly_sql(query: str) -> Optional[str]:
    # 1. 长度限制
    if len(query) > 2000: return "SQL 过长"
    # 2. 剥离注释（防 -- 和 /* */ 绕过）
    normalized = strip_sql_comments(query).strip().rstrip(";").strip()
    # 3. 首关键字白名单
    if first_word not in ("SELECT", "SHOW", "WITH", "EXPLAIN"):
        return "仅支持只读查询"
    # 4. 多语句检测
    if ";" in body: return "检测到多语句执行尝试"
    # 5. 关键字黑名单（词边界匹配）
    if _FORBIDDEN_PATTERN.search(normalized):
        return "包含被禁止的关键字"
```

### 4.4.3 为什么先剥注释

`SELECT 1 -- ; DROP TABLE drugs` 实际只会执行 SELECT 1（-- 后是注释），但如果不剥注释直接匹配关键字，会误杀合法查询；如果完全不检查注释内容，`SELECT 1 /* DROP */` 虽无害但说明模型行为异常。策略：剥注释后校验，注释中的关键字不拦截（因为不会执行），但多语句检测在剥离后进行。

### 4.4.4 表名白名单

```python
_TABLE_NAME_PATTERN = re.compile(r"^[\w一-龥]+$")

def validate_table_name(table_name: str) -> Optional[str]:
    name = table_name.strip().strip("`")
    if not _TABLE_NAME_PATTERN.match(name):
        return "表名包含非法字符"
```

`get_table_data` 的表名进入 SQL 拼接前必须过白名单（仅字母、数字、下划线、中文）。

## 4.5 上传安全

### 4.5.1 三层校验

```python
# 1. 文件名清洗
def sanitize_filename(filename: str) -> Optional[str]:
    name = Path(filename.replace("\\", "/")).name  # 只取 basename
    name = _CONTROL_CHARS_PATTERN.sub("", name).strip().rstrip(".")  # 去控制字符
    if not name or name.startswith("."): return None  # 拒绝隐藏文件
    return name

# 2. 扩展名白名单
def validate_upload(filename: str) -> Optional[str]:
    extension = Path(safe_name).suffix.lower()
    if extension not in {".pdf", ".docx", ".md", ".txt", ".xlsx", ".xls", ".csv"}:
        return "不支持的文件类型"

# 3. 大小上限（流式校验）
while chunk := await file.read(1024 * 1024):
    written += len(chunk)
    if written > max_bytes:
        raise UploadTooLargeError(...)  # 中断并删除半成品
```

### 4.5.2 修复过的缺陷

`strip(".")` 会把 `.env` 的前导点一起剥掉，导致隐藏文件检查被绕过。修复：只剥离尾部点号（`rstrip(".")`），前导点保留供下一步拒绝。

## 4.6 限流

### 4.6.1 两类限流器

```python
# 任务提交：按用户
task_rate_limiter = RateLimiter(max_requests=10, window_seconds=60)
# 登录：按 IP+用户名
login_rate_limiter = RateLimiter(max_requests=5, window_seconds=60)
```

### 4.6.2 滑动窗口实现

```python
class RateLimiter:
    def check(self, key: str) -> tuple[bool, float]:
        now = time.monotonic()
        with self._lock:
            hits = self._hits[key]
            while hits and now - hits[0] >= self.window_seconds:
                hits.popleft()
            if len(hits) >= self.max_requests:
                return False, self.window_seconds - (now - hits[0])
            hits.append(now)
            return True, 0.0
```

### 4.6.3 单用户并发上限

```python
max_concurrent = _max_concurrent_tasks()  # 默认 2
if task_store.count_running(user_id=current_user["id"]) >= max_concurrent:
    raise HTTPException(429, "同时进行的任务数已达上限")
```

计数来自共享 TaskStore，memory/arq 两种模式下都生效。

### 4.6.4 局限与演进

当前限流是进程内内存实现，多实例部署时各 API 实例独立计数。生产环境需要换 Redis 共享计数（已列入后续规划）。

## 4.7 安全配置清单

生产部署必须检查：

- [ ] `AUTH_ENABLED=true`
- [ ] `JWT_SECRET` 改为 32 字节以上随机值（`python -c "import secrets; print(secrets.token_hex(32))"`）
- [ ] `JWT_EXPIRE_MINUTES` 按需调短（默认 1440）
- [ ] `UPLOAD_MAX_MB` 按磁盘容量设置（默认 20）
- [ ] `TASK_RATE_LIMIT` / `MAX_CONCURRENT_TASKS_PER_USER` 按 LLM 预算设置
- [ ] CORS 白名单收紧（当前 `allow_origins=["*"]` 仅适合开发）
- [ ] `.env` 不提交到 Git（.gitignore 已覆盖）
- [ ] MySQL 用户权限最小化（只读查询不需要 DROP 权限）
