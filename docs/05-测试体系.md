# 05 测试体系

## 5.1 测试策略

### 5.1.1 测试金字塔

```
        ┌─────────────┐
        │  E2E 冒烟    │  CLI --mock 模式（评测框架自检）
        │  (少量)      │
        ├─────────────┤
        │  接口测试    │  TestClient 驱动 HTTP/WS（auth/隔离/上传/限流/回放）
        │  (中等)      │
        ├─────────────┤
        │  单元测试    │  工具/存储/队列/指标/评测（主体，241 个用例）
        │  (大量)      │
        └─────────────┘
```

### 5.1.2 核心原则

1. **不依赖外部服务**：LLM、MySQL、Tavily、Redis 全部 mock 或探测跳过；
2. **环境隔离**：所有 SQLite 文件落到系统临时目录（conftest 统一注入）；
3. **确定性**：没有随机失败（时间相关用固定值，并发用事件同步）；
4. **真实代码路径**：mock 只打在最底层（如 MySQLConnectionPool），上层逻辑（缓存、校验）走真实代码。

### 5.2.2 conftest 设计

```python
# 环境变量（在任何 app 模块导入前设置）
os.environ.setdefault("OPENAI_API_KEY", "sk-test-dummy")
os.environ.setdefault("JWT_SECRET", "test-secret-key-...")
os.environ.setdefault("AUTH_DB", "<tmpdir>/users.db")
os.environ.setdefault("EVENT_DB", "<tmpdir>/events.db")
os.environ.setdefault("TASK_QUEUE", "memory")

# 共享 fixture
@pytest.fixture
def session_dir(tmp_path): ...      # 临时会话目录 + ContextVar

@pytest.fixture
def auth_client(): ...              # 已登录 TestClient（唯一用户名）

@pytest.fixture
def second_auth_client(): ...       # 第二个用户（隔离测试）

@pytest.fixture(autouse=True)
def _reset_monitor_singleton(): ... # 每个测试后清理单例
```

**唯一用户名**：测试用户库是共享文件，重复注册同名用户会冲突——用 `uuid.uuid4().hex[:8]` 生成唯一用户名。

## 5.3 Mock 设计

### 5.3.1 FakeEmbeddings（向量库测试）

```python
from langchain_community.embeddings import FakeEmbeddings

fake = FakeEmbeddings(size=32)  # 确定性伪向量
store = FAISS.from_documents(documents, fake)
```

FAISS 全链路（建库→落盘→加载→检索）用确定性向量跑通，不调用真实 Embedding API。

### 5.3.2 MySQL 连接池 mock

```python
class FakeMySQLPool:
    def __init__(self, **kwargs):
        created.append(self)  # 记录创建次数
    def get_connection(self):
        return FakeConn()

monkeypatch.setattr(db_tools, "MySQLConnectionPool", FakeMySQLPool)
```

**只 mock 池构造这一层**：`get_connection_pool()` 的缓存逻辑（配置签名判断）走真实代码，池复用/重建测试才有意义。

### 5.3.3 Agent 执行器 mock

```python
async def fake_run(task_query, session_id, user_id=None):
    return None

monkeypatch.setattr(memory_queue_module, "run_deep_agent", fake_run)
```

**补丁目标**：第二期后任务执行由队列层调度，补丁打在 `app.queue.memory_queue` 模块上（不是 server 模块）。

### 5.3.4 评测 mock

```python
# 假执行器：固定答案
async def fake_agent_runner(query, seed_files=None):
    return "阿莫西林胶囊库存为 5000。", [...]

# 假评审：固定分数
judge = make_mock_judge({"correctness": 0.8, ...})
```

CLI `--mock` 模式用这两个组合跑通全链路，不调用任何外部服务。

## 5.4 关键测试模式

### 5.4.1 跨用户隔离测试

```python
def test_other_user_cannot_read_task(self, auth_client, second_auth_client):
    thread_id = auth_client.post("/api/task", ...).json()["thread_id"]
    response = second_auth_client.get(f"/api/task/{thread_id}")
    assert response.status_code == 404  # 不暴露存在性
```

### 5.4.2 安全回归测试

```python
@pytest.mark.parametrize("sql", [
    "DROP TABLE drugs",
    "SELECT 1; DELETE FROM drugs",
    "SELECT 1 -- ; DROP TABLE drugs",  # 注释绕过
])
def test_blocks_dangerous_sql(self, sql):
    assert validate_readonly_sql(sql) is not None
```

### 5.4.3 指标增量断言

```python
def test_task_submitted_increments(self):
    active_before = metrics_module.TASKS_ACTIVE._value.get()
    metrics_module.record_task_submitted()
    assert metrics_module.TASKS_ACTIVE._value.get() == active_before + 1
```

**为什么用增量**：prometheus 的 Collector 是进程级全局对象，多个测试文件共享（接口测试也会计数），绝对值断言会互相影响。

### 5.4.4 异步测试

```python
async def test_cancel_running_task(self, memory_queue, monkeypatch):
    monkeypatch.setattr(memory_queue_module, "run_deep_agent", cancellable_run)
    submission = await memory_queue.submit("任务", "t-mem-3", None)
    await asyncio.sleep(0)  # 让出一步，确保任务真正启动
    result = await memory_queue.cancel(submission.job_id)
    assert result == "cancelled"
```

`asyncio_mode = "auto"`（pyproject 配置）让 pytest 自动识别 async 测试。

## 5.5 CI 集成

### 5.5.1 CI 流水线（.github/workflows/ci.yml）

```yaml
jobs:
  lint-and-test:
    runs-on: ubuntu-latest
    services:
      redis:
        image: redis:7
        ports: ["6379:6379"]
    steps:
      - uses: actions/checkout@v4
      - uses: astral-sh/setup-uv@v6
      - run: uv sync --frozen --group dev
      - run: uv run --frozen ruff check app tests
      - run: uv run --frozen ruff format --check app tests
      - run: uv run --frozen python -m pytest
```

**Redis 服务**：arq 队列测试探测本地 Redis 可达时才运行，CI 中由 service 容器提供。

### 5.5.2 评测回归（.github/workflows/eval.yml）

- 定时（每周一）+ 手动触发；
- 先跑 `--mock` 冒烟（验证框架）；
- 再跑真实评测（需要 Secrets 配置 API Key）；
- 与上一次运行对比，检出回归即失败；
- 报告存 artifact（保留 90 天）。

## 5.6 测试覆盖的边界

### 已覆盖

- 所有工具函数的输入输出与错误路径；
- 所有存储的状态机与查询；
- 所有接口的认证/授权/参数校验；
- 安全防护的各类攻击向量；
- 评测体系的加载/判定/存储/对比/CLI。

### 未覆盖（及原因）

| 未覆盖 | 原因 |
| --- | --- |
| 真实 LLM 对话质量 | 需要 API Key + 非确定性，由评测体系覆盖 |
| 真实 MySQL 查询 | 需要数据库实例，mock 覆盖逻辑 |
| Docker 镜像构建 | 本机无 Docker，CI 中构建验证 |
| 前端组件测试 | 前端以 tsc + 构建验证，未引入测试框架 |
