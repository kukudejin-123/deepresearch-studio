# 07 部署与运维

## 7.1 部署形态

### 7.1.1 本地开发（memory 模式）

```bash
# 1. 环境
uv sync --group dev
cp .env.example .env  # 配置 LLM/Tavily 密钥

# 2. MySQL 教学库（可选，数据库用例需要）
docker compose -f docker/docker-compose.yaml up -d mysql

# 3. 构建向量库（可选，知识库用例需要）
uv run python -m app.rag.ingest

# 4. 启动
uv run uvicorn app.api.server:app --port 8000 --reload
cd frontend && pnpm dev
```

### 7.1.2 本地开发（arq 模式）

```bash
# 需要 Redis
uv run arq app.worker.tasks.WorkerSettings   # 终端 1
uv run uvicorn app.api.server:app            # 终端 2
```

### 7.1.3 Docker 全栈（推荐体验）

```bash
docker compose up -d                          # api + worker + frontend + mysql + redis
docker compose --profile postgres up -d       # 追加 PostgreSQL
```

访问：

- 前端：http://localhost:8080（Nginx 同源反代）
- API 文档：http://localhost:8000/docs
- 指标：http://localhost:8000/metrics

## 7.2 Docker 架构

### 7.2.1 镜像设计

**后端镜像**（api/worker 共用）：

```dockerfile
FROM python:3.12-slim AS builder
COPY --from=ghcr.io/astral-sh/uv:0.5 /uv /usr/local/bin/uv
COPY pyproject.toml uv.lock ./
RUN uv sync --frozen --no-dev --no-install-project  # 依赖层缓存
COPY app ./app

FROM python:3.12-slim AS runtime
RUN groupadd app && useradd --system app
COPY --from=builder /app/.venv /app/.venv
USER app
HEALTHCHECK CMD python -c "...urlopen('/api/health')..."
CMD ["uvicorn", "app.api.server:app", "--host", "0.0.0.0", "--port", "8000"]
```

**关键设计**：

- 依赖层与源码层分离（源码变动不重装依赖）；
- 非 root 用户运行；
- api 与 worker 共用镜像，compose 中仅覆盖 command。

**前端镜像**：

```dockerfile
FROM node:20-alpine AS builder
RUN corepack enable && pnpm install --frozen-lockfile && pnpm build

FROM nginx:1.27-alpine
COPY nginx.conf /etc/nginx/conf.d/default.conf
COPY --from=builder /build/dist /usr/share/nginx/html
```

### 7.2.2 compose 服务拓扑

```
                    ┌─────────────┐
    浏览器 ────────►│  frontend   │ :8080
                    │  (Nginx)    │
                    └──────┬──────┘
                           │ 同源反代 /api /ws /metrics
                           ▼
    直接访问 :8000 ─────►┌─────────────┐
                         │    api      │
                         │  (FastAPI)  │
                         └──────┬──────┘
                    ┌───────────┼───────────┐
                    │ 入队       │ 订阅       │ 读写
                    ▼           ▼           ▼
              ┌─────────┐ ┌─────────┐ ┌──────────┐
              │  redis  │ │  redis  │ │  SQLite  │
              │ (队列)  │ │(Pub/Sub)│ │ (共享卷)  │
              └────┬────┘ └─────────┘ └────┬─────┘
                   │ 消费                   │
                   ▼                       │
              ┌─────────┐                  │
              │ worker  │──────────────────┘
              │  (arq)  │
              └─────────┘

    依赖服务：mysql:3307（教学数据）、redis:6379
    可选：postgres:5432（profile: postgres）
```

### 7.2.3 数据卷设计（关键）

```yaml
volumes:
  deepresearch_data:      # SQLite（检查点/事件/用户库）+ 向量库
  deepresearch_output:    # 产物文件
  deepresearch_updated:   # 上传暂存
```

**api 与 worker 必须挂载同一组卷**——否则两个容器各写各的 SQLite 文件，任务状态、事件、检查点全部对不上。这是 compose 设计中最容易出错的地方。

## 7.3 配置管理

### 7.3.1 环境变量分组

| 组 | 关键变量 | 生产建议 |
| --- | --- | --- |
| LLM | OPENAI_API_KEY 等 | 必填，用 Secrets 管理 |
| 认证 | AUTH_ENABLED / JWT_SECRET | true + 32 字节随机密钥 |
| 队列 | TASK_QUEUE / TASK_QUEUE_REDIS_URL | arq + Redis 服务地址 |
| 检查点 | CHECKPOINTER_TYPE | postgres（多 worker） |
| 限流 | TASK_RATE_LIMIT / MAX_CONCURRENT_TASKS_PER_USER | 按 LLM 预算调 |
| 上传 | UPLOAD_MAX_MB / UPLOAD_ALLOWED_EXTENSIONS | 按磁盘与业务调 |

### 7.3.2 compose 中的环境注入

```yaml
services:
  api:
    env_file: [.env]           # 基础配置
    environment:               # 容器网络覆盖
      TASK_QUEUE: arq
      TASK_QUEUE_REDIS_URL: redis://redis:6379/0
      MYSQL_HOST: mysql        # 服务名（Docker DNS）
```

**覆盖原则**：`.env` 管密钥与业务配置，`environment` 管容器网络地址（服务名解析）。

## 7.4 监控与可观测

### 7.4.1 Prometheus 指标

```yaml
# prometheus.yml 采集配置示例
scrape_configs:
  - job_name: deepresearch
    static_configs:
      - targets: ["api:8000"]
    metrics_path: /metrics
```

指标清单：

| 指标 | 用途 |
| --- | --- |
| deepresearch_tasks_total{status} | 任务量趋势、失败率 |
| deepresearch_tasks_active | 当前负载（扩容依据） |
| deepresearch_tool_calls_total{tool} | 工具使用分布（优化提示） |
| deepresearch_http_requests_total | 接口 QPS、错误率 |
| deepresearch_task_duration_seconds | 任务耗时 P50/P95/P99 |

### 7.4.2 健康检查

```bash
curl http://localhost:8000/api/health
# {"status": "ok", "task_store": "ok"}
```

不依赖 LLM/MySQL 等外部服务（避免探活误判），只检查进程存活与任务存储可读写。

### 7.4.3 日志

结构化日志格式：

```
2026-10-15 14:43:17 | INFO | app.worker.tasks | worker 接收任务: thread_id=xxx
2026-10-15 14:43:20 | ERROR | app.agent.main_agent | 主智能体执行异常: session_id=xxx
```

接入日志聚合（ELK/Loki）时按 `|` 分割字段即可。

### 7.4.4 多进程指标的注意点

memory 模式下任务提交与结局在同一进程，指标完整。arq 模式下：

- 提交指标（tasks_total{submitted}）在 API 进程；
- 结局指标（completed/failed/cancelled）在 worker 进程；
- **生产环境需要两个进程都接入 Prometheus**（或 Pushgateway），否则指标不完整。

## 7.5 故障排查

### 7.5.1 常见问题

| 症状 | 可能原因 | 排查方法 |
| --- | --- | --- |
| 任务一直 running | worker 没启动/Redis 不通 | 看 worker 日志；`redis-cli ping` |
| WebSocket 连不上 | token 过期/thread 归属 | 看 API 日志的 4404/4401 |
| 事件不推送（arq 模式） | 事件桥未启动 | 检查 TASK_QUEUE_REDIS_URL 配置 |
| 知识库检索失败 | 向量库未构建/Embedding key 缺失 | 跑 `app.rag.ingest`；检查 EMBEDDING_MODEL |
| 数据库查询失败 | MySQL 未启动/配置缺失 | `docker compose ps mysql`；检查 MYSQL_* |
| 任务提交 429 | 限流/并发上限 | 调大 TASK_RATE_LIMIT/MAX_CONCURRENT_TASKS_PER_USER |
| 镜像构建失败 | 网络/缓存问题 | `docker compose build --no-cache` |

### 7.5.2 日志关键字

```
# 启动确认
"服务启动完成（认证已启用，队列 arq）"
"arq worker 启动完成"
"Redis 事件桥订阅循环已启动"

# 任务流转
"任务已提交: thread_id=xxx, 队列=arq"
"worker 接收任务: thread_id=xxx"
"会话执行完成/已被取消/执行异常"

# 安全事件
"下载路径越权，已拒绝: user_id=xxx"
"SQL 安全校验拒绝: ..."
"WebSocket 归属校验失败: thread_id=xxx"
```

## 7.6 容量规划

### 7.6.1 单机容量参考

| 资源 | 容量 | 瓶颈 |
| --- | --- | --- |
| worker 并发 | 4（max_jobs） | LLM 速率限制 |
| 单用户并发 | 2 | LLM 配额 |
| SQLite 写入 | ~100 QPS（WAL） | 任务状态变更频率低，远未触及 |
| 向量库 | 百万级分片 | FAISS IndexFlatL2 暴力检索 |

### 7.6.2 水平扩展

```bash
# 扩展 worker（compose）
docker compose up -d --scale worker=4

# 扩展 API（需要前置负载均衡 + 共享检查点）
# 1. CHECKPOINTER_TYPE=postgres
# 2. 限流换 Redis 共享计数（当前为进程内实现）
# 3. WebSocket 粘性会话或 Redis 适配器（当前为进程内连接表）
```

**扩展的前提**：检查点共享（PostgreSQL）已就绪；限流与 WebSocket 连接表仍是进程内实现，多 API 实例需要改造（已列入后续规划）。

## 7.7 升级与回滚

### 7.7.1 版本升级

```bash
git pull
uv lock && uv sync --group dev   # 依赖变更时
uv run python -m pytest          # 升级前跑测试
```

数据库迁移自动执行（tasks 表 user_id 列的 ALTER TABLE 在 TaskStore 初始化时幂等执行）。

### 7.7.2 回滚

```bash
git checkout <上一个 tag>
# SQLite 数据向前兼容（新列不影响旧代码读取）
```

### 7.7.3 数据备份

```bash
# SQLite 在线备份（WAL 模式下安全）
sqlite3 app/data/checkpoints.db ".backup backup.db"

# 或直接复制（停服后）
cp -r app/data/ data_backup/
```
