# 01 项目介绍（面试版）

## 1.1 一句话介绍

> 格物 · DeepResearch Studio 是一个基于 DeepAgents + LangGraph 的对话式多智能体深度研究平台（基于开源项目二次开发）：用户提出研究任务后，系统自动规划步骤、调度多个专家助手分头获取信息，汇总生成研究报告，执行过程实时可视、可控。

## 1.2 30 秒电梯陈述

> 这个项目解决的是“复杂研究任务自动化”的问题。用户说“查一下药品库存并结合研报生成 PDF”，系统会分解任务：调度网络搜索助手查行业动态、数据库助手查库存、知识库助手检索内部文档，然后汇总生成报告。
>
> 我做的核心工作分三块：一是多智能体架构与工具集成；二是安全与分布式执行——JWT 用户隔离、arq + Redis 任务队列、事件持久化与断线回放；三是质量保障——Agent 评测体系、241 个自动化测试、Docker 部署。
>
> 项目基于开源教学项目二次开发，我在它的骨架上补齐了生产级工程能力，过程中排查修复了 13 个真实缺陷，比如 FAISS 中文路径写入失败、arq 取消接口无限等待挂死、Redis 订阅循环静默死亡等。

## 1.3 简历版描述

**项目名称**：格物 · DeepResearch Studio — 对话式多智能体深度研究平台（基于开源项目二次开发）

**项目地址**：https://github.com/kukudejin-123/deepresearch-studio

**项目介绍**：

> 基于 DeepAgents + LangGraph 的对话式多智能体深度研究平台。用户提出研究任务后，系统自动规划步骤、调度多个专家助手分头获取信息并汇总生成研究报告，执行过程实时可视、可控。

**主要工作**：

1. **搭建**一主三从多智能体深度研究系统（DeepAgents/LangGraph），主智能体调度 Tavily 搜索、MySQL 查询、本地 FAISS 检索三类专家助手，完成多源信息聚合与 Markdown/PDF 报告生成；
2. **设计** JWT 用户体系与按用户资源隔离（任务/文件/知识库），越权访问一律拒绝；工具层落地 SQL 只读校验、上传白名单与接口限流；
3. **重构**单体异步任务为 arq + Redis 分布式队列（任务提交 → 入队 → 独立 worker 执行），API 重启不丢任务、支持水平扩展；执行事件跨进程实时推送，断线后按序号增量回放；
4. **建设**长任务链路可观测性（Prometheus 指标 + 结构化日志），失败可追溯、耗时可度量；会话检查点持久化（SQLite/PostgreSQL），服务重启后恢复会话上下文；
5. **搭建** Agent 评测回归机制（LLM-as-judge 多维评分 + 变更前后对比），提示词与工具改动影响可量化；配套自动化测试与 CI（lint/测试/镜像推送/评测回归），Docker compose 一键部署全栈。

**技术栈**：DeepAgents / LangGraph / LangChain / FastAPI / WebSocket / React / Vite / Redis / arq / FAISS / MySQL / SQLite / PostgreSQL / Prometheus / pytest / Docker / GitHub Actions

## 1.4 项目亮点提炼

### 亮点一：完整的多智能体工程闭环

不是调一次 API 的 demo，而是“规划 → 检索 → 汇总 → 交付 → 可观测”的完整链路。三个专家助手各有专属提示词与工具集，主智能体负责路由与汇总，文件工具直接掌握交付能力。

### 亮点二：13 个真实缺陷的排查与修复

每个缺陷都有完整的“现象 → 排查 → 根因 → 修复”过程，这是证明“真写过代码”的最强素材（详见 04-踩坑复盘.md）。典型如：

- FAISS 中文路径写入失败（C++ 层窄字符 IO）；
- arq 取消接口无限等待挂死（abort 默认 timeout=None）；
- Redis 订阅循环零订阅崩溃（pubsub connection not set）。

### 亮点三：从 demo 到生产的三期演进

安全（认证/隔离/防护）→ 可靠（队列/持久化/可观测）→ 质量与交付（评测/容器化/性能），每期都有明确的问题驱动，不是为做而做。

### 亮点四：Agent 质量可度量

22 用例评测体系 + 三层判定（确定性检查 + 链路检查 + LLM 评审）+ 回归对比。改提示词/工具后跑一次评测就知道变好还是变坏——这是区分“会调 API”和“懂 Agent 工程”的关键标志。

## 1.5 面试官可能的第一反应与应对

| 面试官想法 | 你的应对 |
| --- | --- |
| “又是基于开源项目的” | 主动承认 + 强调改造深度：“原项目是教学骨架，明确声明了六项能力边界，我补齐的就是这些——认证隔离、分布式队列、事件持久化、评测、部署” |
| “多智能体是不是就是调了几个 API” | 讲编排细节：“主智能体的提示词有四条关键约束防幻觉，比如禁止在检索前生成文件、禁止占位符内容；子智能体的 description 设计直接影响路由准确率” |
| “测试写了多少” | 不主动报数字，被问再说：“核心链路都有覆盖，CI 全量在跑，三期重构靠它兜底” |
| “上过生产吗” | 诚实：“没有真实用户流量，但工程链路都验证过——分布式端到端、评测框架、CI 都真实跑过；生产化还差 RBAC、断点续跑这些” |
