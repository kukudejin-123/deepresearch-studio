# 03 开发历程

本文档完整记录三期工程化改造的动机、方案与踩坑过程。这是项目最有价值的部分——每个决策都有真实的问题驱动，每个坑都有排查过程。

## 3.1 起点：原版项目的状态

原项目（didilili/deepsearch-agents）提供了完整的多智能体学习骨架：

**已有的**：

- 一主三从架构（主智能体 + 网络搜索/数据库/RAGFlow 助手）；
- 9 个工具（Tavily、MySQL 三件套、RAGFlow 两件套、文件读取、Markdown、PDF）；
- FastAPI + WebSocket + React 前后端闭环；
- ContextVar 会话隔离、monitor 事件推送。

**原版 README 自己声明的能力边界**：

> 它没有刻意展开以下生产治理能力：用户登录、角色权限和多租户隔离；文件上传安全扫描；任务队列、分布式执行；全量事件持久化；系统化评测集；生产监控、告警、链路追踪。

这六条就是三期改造的需求清单。

## 3.2 第一期：安全与多用户基础

### 3.2.1 动机

原版最大的硬伤：**任何人只要知道 thread_id 就能读写别人的会话**。任务接口、文件接口、WebSocket 全部无认证。这在演示时无妨，但离“能给别人用”差得远。

### 3.2.2 实施内容

**用户体系**（app/api/auth.py）：

- SQLite 用户存储 + PBKDF2-SHA256 密码哈希（标准库实现，不引 bcrypt）；
- PyJWT 签发/校验，`get_current_user` FastAPI 依赖；
- 注册/登录/me 三个接口；前端登录注册页；
- `AUTH_ENABLED=false` 开发模式退路。

**资源隔离**：

- 任务表加 user_id 列（含旧库 ALTER TABLE 迁移）；
- 会话目录/上传目录/输出目录按 `user_{id}/` 分层；
- 任务查询/取消、文件列表/下载全部校验归属，跨用户一律 404；
- 知识库支持用户私有库 + 共享库分层。

**SQL 防护**（app/tools/sql_guard.py）：

- 只读校验（SELECT/SHOW/WITH/EXPLAIN 开头）；
- 关键字黑名单（词边界匹配，不误伤 updated_at）；
- 多语句拦截 + 注释绕过防护；
- 表名白名单。

**上传安全**（app/api/upload_guard.py）：

- 扩展名白名单、流式大小校验、文件名清洗。

**限流**（app/api/rate_limit.py）：

- 滑动窗口：任务按用户、登录按 IP+用户名。

## 3.3 第二期：可靠执行与可观测性

### 3.3.1 动机

第一期解决了“谁能用什么”，第二期解决“执行可不可靠”：

- 任务在 API 进程内执行，服务重启后运行中任务丢失；
- WebSocket 断了执行过程就看不到了；
- 没有任何指标，任务失败只能翻日志。

### 3.3.2 实施内容

**任务队列抽象**（app/queue/）：

- TaskQueue 协议 + memory/arq 双实现；
- 独立 worker 进程（app/worker/tasks.py）；
- 提交接口队列化，入队失败返回 503 并标记 failed（不留僵尸任务）。

**事件持久化与桥**（app/events/）：

- EventStore：SQLite 落库（WAL 多进程并发写）；
- RedisEventBridge：Pub/Sub 跨进程转发；
- 事件回放接口 + 前端 seq 去重。

**协作式取消**：

- 取消接口置位状态，执行侧定期检查主动收尾。

**可观测性**（app/api/metrics.py）：

- Prometheus 四类指标 + 请求计数中间件。

**PostgreSQL 检查点分支**：

- 可选 extra，多 worker 共享会话状态。

## 3.4 第三期：质量体系与部署交付

### 3.4.1 动机

前两期让系统“能跑、安全、可靠”，第三期解决“怎么证明它好”和“怎么交付”：

- 改了提示词/工具，怎么知道 Agent 变好还是变坏？
- 别人怎么一分钟跑起来？

### 3.4.2 实施内容

**评估体系**（app/eval/）：

- 22 用例评测集（六类任务）；
- 三层判定：确定性检查 + 链路检查 + LLM 评审；
- 结果存储 + 回归对比；
- CLI（run/compare/list，--mock 冒烟）。

**容器化**：

- 后端/前端多阶段 Dockerfile；
- compose 全家桶（api/worker/frontend/mysql/redis + postgres profile）；
- Nginx 同源反代。

**CI/CD**：

- docker.yml：镜像构建推送 GHCR；
- eval.yml：每周评测回归。

**性能优化**：

- Embedding LRU 缓存；
- MySQL 连接池；
- 单用户并发上限。

## 3.5 三期演进逻辑

```
第一期：安全      → 解决“谁能用什么”（认证/隔离/防护）
第二期：可靠      → 解决“执行可不可靠”（队列/持久化/可观测）
第三期：质量+交付 → 解决“怎么证明好 + 怎么交付”（评测/容器化/性能）
```

每期都建立在前一期基础上：没有第一期的用户隔离，第二期的多进程共享存储无从谈起；没有前两期的稳定执行，第三期的评测无法可靠运行。
